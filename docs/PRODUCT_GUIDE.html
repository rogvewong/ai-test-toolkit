028 个工具的功能、作用与人效提升

每个工具都是一个独立 Agent，由 5-7 个 substep prompt 编排而成。Agent 自身负责 "应该做什么"和"哪里有风险"，输出结构化报告（HTML/MD/JSON）；人只需读结论 + 决策。

03后续版本开发计划

v0.1 已端到端跑通 8 个 Agent，整体进度约 90%。剩余工作集中在报告体验、 跨 Agent 串联、多端 + CI 集成、团队协作四个方向。

v0.1 当前 · 已完成
8 Agent 端到端跑通 + macOS DMG

8 个工具全部端到端跑通，macOS 79 MB DMG 可分发，3 种连接模式（本地 / OAuth / API Key）， 启动自动检测依赖 + 一键安装，报告管理（HTML/MD/JSON 单条 / ZIP 全部）。

v0.2 1-2 周
报告体验优化（让产品/开发能直接拿来用）

让开发和产品同学打开报告就能拿来用，不用再问测试。

  • 分受众：按"产品视角 / 开发视角 / 测试视角"分块组织报告
  • 结论先行：顶部 5 行执行摘要 — 找到几个问题、哪几个阻塞、谁该改
  • 业务语言：JSON 原文降级到次屏，主屏用业务语言
  • 可操作：每个 issue 标注「操作人 / 修复优先级 / 复现步骤」
  • 双向联动：截图红框 ↔ 问题描述双向跳转
v0.3 2-3 周
跨 Agent 串联 + 用例库

8 个工具的产物自动接力，用例长期累积。

  • 自动接力：step1 需求拆解 → step2 用例设计 → step6 自动化执行 全自动接力
  • 中间产物可编辑：用户能审阅 / 修改 / 拒绝任意一步的 AI 输出
  • 用例库累积：每次跑完的用例存到本地用例库，下次迭代复用
  • 新增工具：「测试报告汇总」 — 把多个 Agent 的产出合并成一份对外发版报告
v0.4 4 周
多端 + CI 集成 + 测试管理同步

从单机工具升级为团队工具链的一部分。

  • Windows / Linux 版本：当前仅 macOS，覆盖更多终端
  • CI 集成：GitLab / Jenkins webhook 触发，PR 自动跑测
  • 用例同步：自动同步到 Jira / 禅道 / TestRail / 飞书任务
  • 新增工具：「性能基线测试」 — Lighthouse / WebPageTest 对比 + 性能回归告警
  • 新增工具：「兼容性矩阵测试」 — BrowserStack/SauceLabs 真机驱动 + 多端截图比对
v0.5 4 周
团队协作（看板 + 评论 + 任务领走）

从单人工具升级为团队工具，多人共享和协作。

  • 报告共享：多人共享同一份报告（云端可选，仍以本地为主）
  • 评论与领走：每条 issue 可评论 / 指派 / 关闭
  • 团队看板：本周生成 / 已修复 / 阻塞中
  • 新增工具：「测试度量与 KPI」 — 缺陷密度 / 用例通过率 / 自动化覆盖率 趋势图
  • 新增工具：「线上故障复盘助手」 — 输入故障描述 → AI 反推用例缺口 → 补到用例库
v1.0 约 3 个月后
稳定版

面向团队稳定使用版本。

  • 全部工具端到端验证通过 30+ 真实业务项目
  • 新增工具：「安全测试」 — OWASP Top 10 自动化扫描 + AI 解读

04开发过程简述

项目从需求探索到 v0.1 端到端跑通，整体节奏分四个阶段。 全程小步快跑、每个 Agent 端到端先打通再优化，避免架构先行的过度设计。

阶段 1
架构选型
底层选 claude-agent-sdk + 本地 CLI

早期对比了 OpenAI Assistants API、LangGraph 自建、本地模型 + LangChain 三条路径。 最终选 claude-agent-sdk：用户复用已有的 Claude 订阅成本最低， SDK 本身处理子进程管理、流式输出、tool calling，自建工作量降到最少。 所有 Agent 用 query() 发指令，工具内部不持有任何 API key。

阶段 2
单 Agent 跑通
从 step2 测试用例设计开始的端到端

最先选了「测试用例设计」作为 0 → 1 的目标 — 因为它是 8 个 Agent 里 ROI 最高的。 电商 H5 PRD 一次跑出 187 条用例，验证了「Agent 编排 + 5-7 个 substep 接力 + JSON 结构化输出」这条路是通的。剩下 7 个 Agent 都按这个模板复制 + 改 prompt。

阶段 3
跨 Agent 共性抽取
提炼通用工作流框架

8 个 Agent 跑通后发现共性：每个都是「读材料 → 拆 substep → 每步 JSON 输出 → 最后聚合成报告」。把这套抽到 packages/workflow/base.py， 每个 Agent 只需要写 prompt + 注册到 TOOL_CATALOG 即可。 新增 H5 / SEO / 弱网三个 Agent 各只用了 1-2 天。

阶段 4
报告 + 工程化
报告聚合 + 截图管线 + macOS 打包

Playwright 跨视口截图 + Claude Vision 视觉分析 + PIL 红框标注 形成三阶段闭环。 报告统一 4 块结构（测试结论 / 风险 / 问题描述 / 用例执行情况）。 PyInstaller 打 macOS .app，pywebview 起原生 WebKit 窗口，启动自动检测依赖 + 一键装。最后用户拿到一个 79 MB 的 DMG，双击就能用。

阶段 5
认证模式调整
三连接模式 + 手动激活原则

早期默认自动复用本机 Claude 凭据。用户反馈"全部人都需要人工手动操作"后改成 unset 默认值， 用户必须在设置页主动选「本地」「OAuth」「API Key」一种才能跑工具。 三种模式的差别只在env处理方式：本地不动、OAuth 强清 key、API Key 强注入。

阶段 6
持续打磨
用户反馈驱动的迭代

每次用户反馈都会被转成 PR 级别的小改动 — 「报告对开发不友好」→ 加 11 字段 ticket schema、 「桌面客户端 vs CLI 混淆」→ 加澄清 banner、「设置页有重复 section」→ 合并到「连接 Claude」。 小步迭代，每次都打 DMG，用户当天就能体验。

主要技术栈： Python (FastAPI + asyncio) · claude-agent-sdk · pywebview (macOS 原生窗口) · Playwright (跨浏览器截图) · PIL (图像标注) · PyInstaller (打包) · 纯前端原生 JS（无框架）
开发原则： 先端到端再深度（先把 8 个跑通再优化任何一个）· 本地优先（数据不上云，订阅认证不走自建后台）· 不重复造轮子（Claude SDK 提供的能力直接用，不二次封装）· 小步迭代（每次改动都打 DMG 让用户当天试）。
