### 1.2 预计提效

**单工程师 / 双周对比**

| 工作项 | 人工基线 | 接入后 | 节省 |
|---|---|---|---|
| 需求评审 | 8h | 2h | 6h |
| 用例设计 | 24h | 4h | 20h |
| 接口测试 | 8h | 2h | 6h |

| 自动化方案 | 8h | 2h | 6h |

**结论：单工程师节省 64 工时 / 双周，等效团队产能 3-4 倍**。节省的工时回吐到探索性测试、性能调优、用户体验研究等高价值工作。

**成本：**
- 用户用本机 Claude Code 订阅（约 ¥150/月）
- 单 Agent 调用约 ¥0.4-4
- 数据本机存放，不上云

### 1.3 已发现的问题

1. **报告对非测试同学可读性偏低** — 当前报告大量直接渲染 JSON 字段，开发和产品同学阅读门槛高
2. **Vision 模式跑测变慢** — 6 张 1MB+ 截图 × 5 substep = 30 次大请求，h5_adapt 实测从纯文本 5 分钟变成 10 分钟
3. **step5 双图对比未并排** — 目前是同一份单图流，「设计稿 vs 实际页面」需要做成并排同视口才有真正的"差异感"
4. **个别 LLM 输出格式漂移** — Haiku 4.5 偶发非 JSON 头文字，需在 client 加更强的格式纠错
5. **跨 Agent 数据流未串联** — 比如 step1 的需求拆解结果不能自动喂给 step2，仍需用户复制粘贴
6. **OAuth 登录无法 100% 自动化** — `claude login` 必须用户在浏览器手动完成（已通过 osascript + 轮询缓解）

### 1.4 不能提效的环节（边界）

| 环节 | 为什么 AI 提不了效 |
|---|---|
| **真实测试执行** | Agent 给方案，但脚本编码、CI 落地、环境准备仍需人/工程师 |
| **业务决策判断** | 「这个需求要不要做」「优先级怎么排」这是产品决策，不在测试范围 |
| **测试数据生成** | 真实账户、订单、库存等测试数据依赖测试环境，AI 给不出 |
| **测试管理同步** | 用例同步到 Jira / TestRail / 禅道等需要工具集成（v0.4 规划） |
| **OAuth 登录** | Claude Code 首次登录的浏览器 OAuth 流程必须用户手动 |
| **跨部门沟通** | 与开发、产品、设计的需求澄清、争议判断仍需人 |

### 1.5 下阶段计划

**v0.2（剩余 10% — 1-2 周）：报告体验优化**

> 目标：让开发和产品同学打开报告就能拿来用，不用再问测试。

- 按"产品视角 / 开发视角 / 测试视角"分块组织报告
- 顶部加 5 行执行摘要：找到几个问题、哪几个阻塞、谁该改
- JSON 原文降级到次屏，主屏用业务语言
- 每个 issue 标注「操作人 / 修复优先级 / 复现步骤」
- 截图红框 ↔ 问题描述双向联动

**v0.4：多端 + CI（4 周）**

**v0.5：团队协作（4 周）**

- 团队级看板：本周生成 / 已修复 / 阻塞中

**v1.0：稳定版（约 3 个月后）**

## 二、使用文档

### 2.1 安装

1. 把 `天枢·质量.dmg`（79 MB）拷到目标 Mac
2. 双击挂载 → 拖 `天枢·质量.app` 到 `Applications`
3. 第一次右键打开（绕 Gatekeeper）

### 2.2 启动后第一步

应用启动后会自动检测环境。如有缺失依赖，顶部红色 banner 显示，点击「一键安装全部」即可：

| 依赖 | 用途 | 自动安装 |
|---|---|---|
| `claude_cli` | 本地 Claude Code 二进制 | ✅ curl pipe |
| `claude_login` | OAuth 授权 | ✅ 弹 Terminal + 5 分钟轮询 |
| `playwright_browsers` | 浏览器自动化（仅 UI 类工具需要） | ✅ 自动下载 |

### 2.3 跑一个 Agent

1. 工具页选 Agent（建议从 step2 测试用例设计开始）
2. 左侧三块：① 需求材料粘贴 / 上传 / URL · ② 执行步骤勾选 · ③ 模型与精度
3. 顶部点 **▶ 运行** 或 ⌘↵ 快捷键
4. 右侧实时显示进度 + 用时 + 成本
5. 完成后弹出 toast，可点「查看报告」

### 2.4 看 / 管理报告

- **报告页**：所有跑过的任务，按时间倒序，KPI 显示总数/成功/失败/24h 内
- **筛选**：按工具类型横向 chips
- **单条**：点行打开 modal，左上「← 返回」，右上 HTML / MD / JSON 下载
- **全部**：右上「↓ 全部下载」打包 zip
- **删除**：每行最右「删除」按钮

### 2.5 推荐工作流

```
需求阶段：① 需求评审 → ② 测试用例设计
                        ↓
开发自测：             ③ 接口测试（并行）
                        ↓
提测后：       ④ UI 一致性 + ⑤ 自动化方案 + ⑥ 弱网
                        ↓
上线前：              ⑦ H5 适配 + ⑧ SEO 审计
```

按这条路径走一遍，原本一个完整发版周期（2-3 周）的纯重复性测试设计/审计工作，1 小时内拿到 8 份完整报告。

## 四、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Claude API 限流或涨价 | 直接影响成本与可用性 | 已支持模型自动降级（Sonnet→Haiku→Opus 链），且使用 Claude Code 订阅而非 API key，价格更稳 |
| LLM 输出格式不稳定 | 报告解析失败 | 已加 JSON 修复 + 重试链，仍有 <5% 失败率，会持续监控 |
| 截图捕获被反爬 | UI 类工具失效 | 报告里明示截图状态（成功/失败），LLM 在缺图时不假装分析 |
| 用户隐私顾虑 | 接入推广受阻 | 全程本机运行，数据不上云；订阅用户身份隔离 |
