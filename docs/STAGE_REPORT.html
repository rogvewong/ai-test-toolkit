2已发现的问题

实测过程中暴露的真实问题，部分已纳入 v0.2 计划。

  • 报告对非测试同学可读性偏低 — 直接渲染 JSON 字段，开发和产品阅读门槛高。→ v0.2 重写
  • Vision 模式跑测变慢 — 6 张 1MB+ 截图 × 5 substep = 30 次大请求；h5_adapt 从 5 分钟变 10 分钟
  • step5 双图未并排 — 「设计稿 vs 实际页面」需要做成同视口并排呈现差异感。→ v0.2 改
  • 个别 LLM 输出格式漂移 — Haiku 4.5 偶发非 JSON 头文字，需在 client 加更强格式纠错
  • 跨 Agent 数据流未串联 — step1 拆解结果不能自动喂 step2，仍需用户复制粘贴。→ v0.3 做
  • OAuth 登录无法 100% 自动 — 已通过 osascript + 5 分钟轮询缓解，仍需用户在浏览器点确认

3不能提效的环节（边界）

把"哪些事 AI 帮不了"明确出来，避免预期错位。

环节为什么 AI 提不了效
真实测试执行Agent 给方案，但脚本编码、CI 落地、环境准备仍需工程师
业务决策判断「这个需求要不要做」「优先级怎么排」属产品决策，不在测试范围
测试数据生成真实账户、订单、库存等依赖测试环境，AI 给不出

OAuth 登录Claude Code 首次登录的浏览器 OAuth 必须用户手动
跨部门沟通需求澄清、争议判断仍需人

4使用文档

4.1 安装

  1. 把 天枢·质量.dmg（79 MB）拷到目标 Mac
  2. 双击挂载 → 拖 天枢·质量.app 到 Applications
  3. 第一次右键打开（绕 Gatekeeper）

4.2 启动后第一步

应用启动后会自动检测环境。如有缺失依赖，顶部红色 banner 显示，点击「一键安装全部」即可。

依赖用途自动安装
claude_cli本地 Claude Code 二进制✓ curl pipe
claude_loginOAuth 授权✓ 弹 Terminal + 5 分钟轮询
playwright_browsers浏览器自动化（仅 UI 类工具需要）✓ 自动下载

4.3 跑一个 Agent

  1. 工具页选 Agent（建议从 step2 测试用例设计 开始）
  2. 左侧三块：① 需求材料粘贴 / 上传 / URL · ② 执行步骤勾选 · ③ 模型与精度
  3. 顶部点 ▶ 运行 或按 ⌘ ↵
  4. 右侧实时显示进度 / 用时 / 成本
  5. 完成后弹 toast，可点「查看报告」

4.4 看 / 管理报告

  • 报告页：所有跑过的任务，KPI 显示总数 / 成功 / 失败 / 24h 内
  • 筛选：按工具类型横向 chips
  • 单条：点行打开 modal，左上「← 返回」，右上 HTML / MD / JSON 下载
  • 批量：右上「↓ 全部下载」打包 ZIP
  • 删除：每行最右「删除」按钮（双重确认）

4.5 推荐工作流

需求阶段：① 需求评审 → ② 测试用例设计 ↓ 开发自测： ③ 接口测试（并行） ↓ 提测后： ④ UI 一致性 + ⑤ 自动化方案 + ⑥ 弱网/断网 ↓ 上线前： ⑦ H5 适配 + ⑧ SEO 审计

按这条路径走一遍，原本 2-3 周的纯重复性测试设计/审计工作，1 小时内拿到 8 份完整报告。

6风险与应对

风险影响应对
Claude API 限流或涨价 直接影响成本与可用性 已支持模型自动降级（Sonnet → Haiku → Opus 链）；用 Claude Code 订阅而非 API key，定价更稳
LLM 输出格式不稳定 报告解析失败 已加 JSON 修复 + 重试链；当前失败率 <5%，持续监控
截图捕获被反爬 UI 类工具失效 报告里明示截图状态（成功/失败），LLM 在缺图时不假装分析
用户隐私顾虑 接入推广受阻 全程本机运行，数据不上云；订阅用户身份隔离
