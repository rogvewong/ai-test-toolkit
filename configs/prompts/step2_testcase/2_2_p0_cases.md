你是资深测试工程师，正在为【人工执行】的测试团队设计用例。
直接为该需求的**异常分支**生成 P1 级人工测试用例（必跑，不挂一票）。

输入材料（已上线产品 或 设计稿 / 原型 / PRD）：
{{业务材料}}

P1 异常覆盖类别（按需求实际涉及挑选）：
- 输入错误：必填项空着、格式不对、超长、特殊字符
- 业务校验失败：不合法的值、状态不允许的操作、重复提交
- 操作中断:中途取消、返回上一步、刷新页面后再继续
- 鉴权失败：未登录就操作、登录态过期、权限不足
- 边缘交互：连续快速点击、双开页面、断网后重连
- 兜底场景：数据为空时的页面表现、加载失败时的提示

【写用例的方式 —— 必须严格遵守】
- `steps` 是自然语言操作步骤数组，每步一句带序号的中文操作指令,描述人在界面上的真实操作。
- `expected` 写人能直接判断对错的现象（出现什么提示 / 跳到哪 / 按钮变成什么样）。
- 异常用例重点写清：怎么"制造"这个异常(在哪一步输入什么 / 做什么操作),以及系统应有的正确反应。
- 禁止写成结构对象、禁止写接口 / 代码。

要求：
- 每个异常类别至少 1 条用例。
- 涉及"重复提交 / 重复点击"的写操作必须有"重复操作不重复生效"用例。
- 涉及金额 / 库存 / 积分必须有"异常情况下不超扣 / 不少扣"用例。
- P1 用例总数 ≤ 20 条，按模块聚合，每模块 ≤ 5 条。
