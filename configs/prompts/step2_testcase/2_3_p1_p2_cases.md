## 从覆盖矩阵接力 + 穷尽展开
2_1 已标出每个功能点适用的 `exception` / `boundary` 维度。本步**对每个功能点逐项展开**，**禁止用"等/类似/若干/包括但不限于"含糊带过**——适用的场景必须逐条写成用例。

### A. 异常分支（exception）——对每个输入、每个分支
逐条枚举（适用才写）：
- **必填校验**：每个必填项**各自**空着提交一条。
- **格式校验**：每个有格式要求的字段（手机号/邮箱/身份证/金额）填非法格式各一条。
- **业务校验失败**：不合法的值、当前状态不允许的操作、超出额度/库存。
- **重复 / 幂等**：连续快速点两次提交、表单重复提交——写操作必须有"重复操作不重复生效（不生成两单/不重复扣款）"用例。
- **操作中断**：中途取消、返回上一步再进来、刷新页面后继续。
- **鉴权失败**：未登录就操作、登录态过期后操作、权限不足（垂直越权细化留 2_4，这里出"态过期/未登录"基础兜底）。
- **兜底 / 失败态**：列表数据为空时的空态、加载失败时的提示、网络异常的提示。
- **并发 / 时序**（仅当材料暗示有并发/库存/余额诉求）：两端同时操作同一资源。

### B. 边界值（boundary）——对每个输入的边界
对每个有取值范围的输入，逐条覆盖：
- **数值**：最小值 / 最小值−1 / 最大值 / 最大值+1 / 0 / 负数。
- **文本长度**：空 / 1 字 / 中间长度 / 最大长度 / 最大长度+1（超字段长）。
- **字符类型**：纯中文 / 纯英文 / 纯数字 / emoji / 特殊符号 / 前后空格 / 全空格。
- **金额精度**：最小币种单位 / 多位小数 / 0 元 / 负数 / 超额度。
- **数量**：0 条 / 1 条 / 上限 / 上限+1。
- **时间**：活动开始前一刻 / 刚开始 / 刚结束 / 结束后一刻 / 跨天 / 跨月 / 跨年。
- 每条用例聚焦**一个**具体边界值。

### 深度标杆（必须达到这个穷尽度）
以"登录"为例，**应当**长出（材料涉及到才出对应条）：空账号 / 空密码 / 账号前后空格 / 大小写敏感性 / 超长账号(>字段长) / 账号含 SQL 字符 `' OR 1=1`（注入归 security，放 2_4） / emoji 账号 / 密码连错 1→N 次触发锁定 / 锁定时长边界 / 锁定期间用正确密码 / 解锁后重试 / 验证码过期 / 验证码重放 / 未注册号登录 / 已注销账号登录 / 已冻结账号登录 / 首次登录强制改密 / 密码到期 …… 每条带前置+步骤+单一可断言预期+判定依据。**其它功能点要拿出同等穷尽度。**

## 分域标准测试点清单（Domain Checklist）—— 系统性兜底，防漏域（本步必跑）

上面 A/B 是「自由穷尽」，本节是「按业务域逐条对表设计用例」，专治「临场想不到、系统性漏掉」（实测漏过：套餐升级降级差价、并发设备数/防账号共享、风控盗刷）。**这份域清单与第 1 步（需求评审）的 1_4、以及本工具 2_4 共用同一份，口径必须一致。**

用法（强制流程）：
1. **先判定材料涉及哪些域**（只要有一句话/一个字段/一个按钮指向该域功能即算「涉及」），在 `domain_coverage[].applicable` 记 `true/false`。
2. **对每个涉及的域，把下面属于「异常/边界性质」的点逐条设计成可执行用例**——凡适用必列尽，禁止用「等/类似/若干」带过。每个点至少一条用例，确实需要多条（如「支付结果分支」有 7 种结果）就拆成多条，每条聚焦一种。
3. **分工边界**（共用同一清单、按性质分到不同步骤，避免重复也避免遗漏）：
   - **本步 2_3 负责**：清单里属于**异常分支 / 输入边界 / 幂等去重 / 金额精度 / 时序并发**性质的点（下面已用 ⟦2_3⟧ 标注）。
   - **2_4 负责**：清单里属于**权限/越权/安全/状态机非法流转**性质的点（下面已用 ⟦2_4⟧ 标注）；本步**不重复**这些，但若某点同时跨异常与状态机（如「订单超时自动关单」），本步出「超时未支付后再点支付被拒」的异常用例，状态机流转那一跳留 2_4。
4. **PRD 没定义该点怎么处理时**：用例照常设计（步骤照常写），但 `expected` 写「材料未规定 X 的处理方式，需澄清」、`ambiguity` 标 `true`，并确保该歧义已登记进 2_1 `open_questions`（`remark` 注明对应 Q 编号）。**绝不替产品二选一编预期。**
5. **这是最低覆盖基线，不是上限**：清单是地板不是天花板。材料涉及但本清单没列到的子点/子域，**自行类比展开**补设计用例，在 `domain_coverage[].extra_cases_added` 说明补了哪些。

### D1 · 支付 / 交易域（材料涉及下单、付款、收银台、交易、退款、对账任一即适用）
逐点设计用例（标 ⟦2_3⟧ 的本步出，⟦2_4⟧ 的留 2_4）：
- ⟦2_3⟧ **下单**：重复下单各一条、并发下单（同用户/同商品同时多次提交）一条、同一商品存在多笔未支付订单一条、跨端下单（H5 下单 APP 继续付）一条。
- ⟦2_3⟧ **支付结果分支**：成功 / 失败 / 用户取消 / 超时未结 / 关单后到账 / 部分支付 / 支付中关闭页面——**每种结果各一条**，断言订单状态与用户所见。
- ⟦2_3⟧ **幂等**：支付回调重复通知不重复开通一条、同订单重复开通权益只发一次一条、重复点击不重复扣款一条（用例点明幂等键=订单号+交易号）。
- ⟦2_3⟧ **回调**：异步回调丢失/延迟/乱序后查单兜底一条、主动查单与回调状态冲突时以谁为准一条（伪造回调验签归 2_4 安全）。
- ⟦2_3⟧ **金额**：0 元一条、负数一条、超大额一条、分/元精度与四舍五入一条、优惠后金额计算与展示一条（**篡改金额**归 2_4 越权/安全）。
- ⟦2_3⟧ **对账**：支付平台与本地状态长时间不一致一条、掉单一条、长时间未回调一条（断言系统有对账/告警/补偿，PRD 没定义则标待澄清）。
- ⟦2_3⟧ **退款**：全额退款一条、部分退款一条、退款后权益回收与到期时间调整一条、退款幂等（不重复退）一条、超时退款一条、已消费部分如何算一条。
- ⟦2_3⟧ **价格**：下单锁价快照一条、改价对「未下单 / 已下单未付 / 支付中」分别的影响各一条、展示价与下单价不一致以谁为准一条。
- ⟦2_4⟧ **风控**：盗刷、异常交易频次、同卡多账号/同账号多卡、黑产批量、风控拦截后体验——留 2_4 安全。
- ⟦2_4⟧ **订单状态机**：各状态非法跳转、各状态允许的操作、超时自动关单的状态流转——留 2_4 状态机（本步只出「超时后再操作被拒」这类异常面）。

### D2 · 订阅 / 会员域（材料涉及会员、套餐、订阅、续费、权益、有效期任一即适用）
逐点设计用例：
- ⟦2_3⟧ **套餐变更**：升级一条、降级一条、差价补/退各一条、不同时长套餐时长换算一条、跨档变更生效时点（立即/下周期）一条。
- ⟦2_3⟧ **续费**：有效期内续费时长叠加（原到期日顺延 vs 从今天重算）一条、到期后重购一条、连续包月周期一条。
- ⟦2_3⟧ **自动续费**：是否自动扣款一条、解约一条、扣款失败重试一条、到期前扣款时点一条（产品有自动续费才出）。
- ⟦2_3⟧ **到期**：到期判定精确到时刻+时区一条、到期当天可用性一条、宽限期一条、降级/失权触发时机与定时任务时点一条。
- ⟦2_4⟧ **并发**：同一会员多设备同时在线数上限、防账号共享、异地同时登录、顶号策略——留 2_4（属并发/权限性质，本步只出「超出设备数时新登录的提示」这类用户可见异常面，顶号的会话失效逻辑留 2_4）。
- ⟦2_3⟧ **权益边界**：免费 vs 专属边界一条、清晰度权限矩阵（游客/注册未付费/会员 × 免费/专属）逐格、试看片段一条、全端权益通用与登录态跨端同步一条。
- ⟦2_3⟧ **提醒**：到期前提醒时点/渠道/去重/触发次数各覆盖一条。

### D3 · 权限 / 越权域
⟦2_4⟧ 整域留 2_4（垂直越权、水平越权、直链绕过、鉴权 token）。**本步不出**，仅在此列出以保持清单完整、便于核对。

### D4 · 通用必查（所有功能都要对一遍，不分域）
逐点设计用例：
- ⟦2_3⟧ **输入**：空 / 超长(超 DB 字段) / 特殊字符 / emoji / 前后空格 / 大小写敏感 各代表性一条（**SQL-XSS-命令注入字符**归 2_4 安全）。
- ⟦2_3⟧ **并发与时序**：竞态一条、重复提交一条（状态机非法跳转留 2_4）。
- ⟦2_3⟧ **i18n**：中英混排一条、占位符泄漏一条、时区一条（仅当材料暗示需多语言/跨时区）。
- ⟦2_3⟧ **网络**：弱网一条、断网一条、超时一条、重试幂等一条（提示与恢复行为）。
- ⟦2_4 / 2_5⟧ **可观测**：关键操作埋点、错误日志——属信息性核查，用例性弱，归 2_4 或在 2_5 作为 issue/待澄清登记，本步不强凑。

## 每条用例的硬要求
- `preconditions`：精确前置，含要构造的数据/账号/初始状态。
- `steps`：自然语言带序号操作数组，**重点写清"怎么制造这个异常/边界"**——在哪一步、哪个输入框、填入什么具体值、做什么操作。禁止结构对象 / 接口 / 代码。
- `expected`：**单一可断言**的现象（出现什么具体文案 / 跳到哪 / 按钮变什么样 / 数据没被改）。禁止"显示正常"。
- **超时 / 锁定时长 / 自动过期类**用例：必须在 `remark` 标注「需配合调小超时配置触发，非真实干等 N 分钟」，并写出触发方式。

## 边界预期的防幻觉（关键）
- 边界的预期**不允许写"接受或拦截都算对""提示 A 或 B 都行"**。需求规定了就照规定写死预期；**需求没规定**这个边界怎么处理，就**不要二选一**——把 `expected` 写成「材料未规定 X 边界的处理方式」，把 `ambiguity` 标 true，并确保这条歧义已登记进 2_1 `open_questions`（在 `remark` 注明对应 Q 编号）。
- 材料里没有的阈值（最大长度、锁定次数、超时分钟、金额上限），**绝不编造**。用例可以写"输入超过【字段最大长度】的字符串"，把具体数字留作 `<待澄清>`，不要硬填一个 21、255。
- 凡材料未定义的行为，不臆造系统反应。

## 优先级（按影响逐条判定，不要写死"异常=P1 / 边界=P2"）
判定标准：**P0**=破了导致主流程不可用 / 资金/订单/库存/数据正确性受损（如"重复提交生成两单""超额下单不拦截"）→ 即便是异常/边界也给 **P0**；**P1**=重要功能受损但有绕行、关键校验缺失；**P2**=次要/边缘体验；**P3**=纯提示性（文案微差）。**异常不等于 P1、边界不等于 P2**——按这条用例真实的业务影响给。
- 涉及金额 / 库存 / 积分的异常，必须有"不超扣 / 不少扣 / 不超卖"用例，优先级按资损影响通常 P0。
- 用例数克制：按模块聚合，避免机械组合灌水；同一字段的同类边界不必把每种特殊符号都列满，挑有代表性的（emoji / 空格 / 注入字符各一类即可）。

## 去重规则（强制，本工具所有出用例步骤统一遵守）
- **同一（功能点 + 测试意图）只出一条用例**。不要把同一个验证点反复出。例如「下单 0 元」只一条，不要既出一条「现状：0 元能下单」又出一条「应有：0 元应拦截」。
- **禁止把"现状观察"和"应有预期"拆成两条**：本工具是分析型、没真跑系统，不存在"观察到的现状"。一个测试意图 = 一条用例：
  - 该测什么的步骤照常写进 `steps`；
  - **应有的判定结果写进 `expected`**（材料规定了照写，没规定就标 `ambiguity:true` 写「待澄清」，不二选一）；
  - 若需要引用材料原文作为预期依据，放进 `evidence`，**不要**因此另开一条用例。
- 跨步骤去重：本步（异常/边界）与 2_2（主流程）、2_4（权限/安全/状态机）若出现意图重叠，按性质归位、只在其归属步出一次（分工见上「分域清单·分工边界」）；2_5 会再做一轮全集去重，但各步自身先不要制造重复。
