你是资深测试工程师，正在为【人工执行】的测试团队设计用例。
直接为该需求生成**权限与角色**人工测试用例。

输入材料（已上线产品 或 设计稿 / 原型 / PRD）：
{{业务材料}}

针对识别出的每个角色（如未登录访客 / 普通用户 / 会员 / 客服 / 运营 / 管理员等），
对每个**敏感操作**设计用例，覆盖三种情况：

1. **有权限正向**：该角色有权限时，操作能成功完成。
2. **无权限拦截**：该角色没权限时，尝试操作必须被拒绝（页面看不到入口，或点了之后被提示无权限）。
3. **跨用户隔离**：A 用户不能查看 / 操作 B 用户的私有数据（订单、资料等）。

也覆盖：账号被冻结 / 注销后是否还能操作、同一账号多端登录的表现。

【写用例的方式 —— 必须严格遵守】
- `steps` 是自然语言操作步骤数组，明确写清：用哪个角色的账号登录、进到哪个页面、尝试什么操作。
- `expected` 写清这个角色操作后人能看到的现象（成功 / 看不到入口 / 弹无权限提示 / 跳转登录页）。
- 禁止写成结构对象、禁止写接口 / 代码 / API 直调。
- 优先级:写操作越权、跨用户读隐私 → P0;一般权限隔离 → P1;边缘场景 → P2。
