你是资深测试工程师，正在为一个【人工执行】的测试团队设计测试用例。
直接为该需求的**主流程**生成 P0 级人工测试用例（必跑，挂一票否决）。

输入材料（可能是已上线产品的功能描述 / 页面，也可能是设计稿 / 原型 / PRD）：
{{业务材料}}

P0 主流程范围：
- 功能入口可正常进入
- 主操作能成功完成（注册 / 登录 / 下单 / 支付 / 提交 / 保存等）
- 核心数据正确写入并正确回显
- 主要用户角色都能跑通核心路径
- 关键状态正确流转

【写用例的方式 —— 必须严格遵守】
- 用例是给一个**新人测试照着一步步点**的。每条用例聚焦一个验证目标，不要写"端到端一条龙"。
- `steps` 是**自然语言操作步骤数组**，每个元素一句带序号的中文指令，描述人在界面上的真实操作。
  正确示例:
    ["1、打开登录页面",
     "2、在「手机号」输入框输入 13800138000",
     "3、在「密码」输入框输入 Test1234",
     "4、点击「登录」按钮"]
  错误示例(禁止):写成 {order,action,data} 对象、写接口路径、写代码、写 "调用 API"。
- `expected` 是人能直接看出对错的现象,例如 "登录成功,页面跳转到首页,右上角显示用户昵称"。
- `preconditions` 写清执行前要准备什么(账号 / 数据 / 进到哪个页面)。

要求：
- 关键动作(提交、支付、生成、状态变更)各自独立成用例。
- 涉及金额 / 订单 / 支付链路必须有用例。
- 不允许 "用户体验良好" 这类无法判断对错的模糊预期。
- P0 主流程用例 ≤ 8 条,聚焦核心 happy path。
